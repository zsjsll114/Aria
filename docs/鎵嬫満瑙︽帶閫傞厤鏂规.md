# 手机触控适配方案（设计文档 · 仅方案不含实现）

> 适用对象：本歌词播放器 Web 应用。前置基础：≤700px 断点下已启用手机版双页布局
> （播放控件页 + 歌词页 + 中央切换按钮）。本文档描述在其之上补齐完整触控体验的设计。

---

## 一、目标与原则

1. **拇指友好**：所有高频操作（播放/暂停、切歌、拖进度、拖音量、切页）单手可达，命中区不小于 44×44px（Apple HIG / Material 双标准取交集）。
2. **零学习成本**：手势遵循系统级直觉——左右滑切页、上下滑滚歌词、点按确认、长按更多。
3. **不破坏桌面**：所有触控增强通过 Pointer Events 与媒体查询（`pointer: coarse` / `hover: none`）作用域限定，桌面行为零改动。
4. **性能红线**：移动端 GPU/电池受限，动效与视觉化必须可降级。

---

## 二、断点与输入模式判定

| 维度 | 判定方式 | 用途 |
|---|---|---|
| 宽度断点 | `@media (max-width: 700px)`（已存在） | 双页布局切换 |
| 触控能力 | `@media (pointer: coarse)` + `hover: none` | 启用触控专属样式（更大命中区、去 hover 态） |
| 运行时探测 | `navigator.maxTouchPoints > 0 && matchMedia('(pointer: coarse)')` | JS 侧手势开关 `IS_TOUCH`，二合一条件避免触屏笔记本误判 |
| 横竖屏 | `matchMedia('(orientation: landscape)')` | 横屏策略（见第七节） |

要点：**布局断点（宽度）与触控断点（输入方式）解耦**。窄屏键鼠设备（如分屏窗口）保留点击逻辑；宽屏触屏设备（平板）只放大命中区不强制双页。

---

## 三、手势系统设计

### 3.1 双页横滑切换（P0）
- 在两页内容区监听 Pointer 事件：`pointerdown` 记录起点，`pointermove` 跟随位移使当前页产生 `translateX` 预览（阻尼系数 0.6），`pointerup` 判定。
- **判定阈值**：横向位移 ≥ 48px **且** |dx| > |dy| × 1.5 → 切页；否则回弹。
- 切页动画复用现有 `mobile-page-in` 关键帧体系，时长 280ms，与点击切换按钮行为一致。
- 歌词页内**纵向**滚动歌词时锁定横滑（dy 优先判定），避免滚动歌词误切页。

### 3.2 滑条触控化（P0）
- 进度条 / 音量条改用 Pointer Events 统一处理 `pointerdown → setPointerCapture → pointermove → pointerup`，替代现有 mouse 事件组合（触屏不再依赖 mouse 事件模拟）。
- **拖动预览、松手提交**：进度条拖动中只更新 UI（进度条宽度 + 时间文字），`pointerup` 才写 `audio.currentTime`——避免拖动中音频频繁 seek 卡顿。
- **热区扩展**：轨道视觉高度不变，用 `padding: 12px 0` + `background-clip: content-box`（或伪元素）把实际命中高度扩到 ≥40px。
- 拖动中给轨道加 `.scrubbing` 类：进度点放大 1.3 倍 + 时间气泡跟随，松手淡出。

### 3.3 歌词区交互（P0/P1）
- **点按行跳转**（已有）保留；增加 **200ms 滚动保护窗**：惯性滚动结束后 200ms 内的 tap 不触发行跳转（区分"滚动刹车"与"选行"意图）。
- **长按行（≥450ms）弹出操作浮层**：复制歌词 / 收藏歌曲 / 仅播放此曲。用 `contextmenu` 事件统一（长按在移动端触发 contextmenu），桌面右键天然复用。
- **快速拖动回中**：歌词区右侧增加细长拖动条（类似网易云"按住滚动歌词"），拖动时中央显示目标行大字预览（P2 增强）。

### 3.4 播放控件页增强（P1）
- **封面双击 = 播放/暂停**（单击保留给"打开歌词页"语义冲突时改用双击封面区）。
- **边缘横滑 = 切歌**：屏幕左 1/4 区域右滑 = 上一曲，右 1/4 左滑 = 下一曲（与 3.1 页切换通过区域互斥，仅播放页启用）。
- 音量图标单击静音切换（已有）保持。

### 3.5 词云/飞入等可视化模式（P1）
- 词云拖拽已有 pointer 逻辑，补 `touch-action: none` 于词云容器，防止拖词时浏览器接管滚动。
- 双指捏合（pinch）缩放词云相机距离（P2）：两指距离变化映射相机 z，单指仍为拖拽。

## 四、防误触与冲突仲裁

| 冲突场景 | 仲裁策略 |
|---|---|
| 歌词滚动 vs 行点击 | 惯性滚动保护窗 200ms（3.3） |
| 横滑切页 vs 页内滚动 | 位移方向占优判定（|dx| > 1.5|dy|），一旦锁定方向本次手势不反悔 |
| 双击缩放页面 | 全局 `touch-action: manipulation`；播放器根节点 `touch-action: pan-y`（歌词区）/ `none`（滑条、词云）按区域覆盖 |
| 长按选中文字 | 可交互控件与歌词行 `-webkit-user-select: none`；正文按钮/输入框保留选择能力 |
| iOS 橡皮筋回弹 | 双页容器 `overscroll-behavior: contain`；页面级滚动锁定在歌词页内部消化 |
| 弹出子菜单外点关闭 | 现有 stopPropagation 体系补一层透明遮罩层（视觉无感，仅拦截穿透点击） |

## 五、性能与功耗降级

1. **可视化模式自适应**：`IS_TOUCH` 或 `navigator.hardwareConcurrency <= 4` 时，粒子类视觉化（星云/粒子）自动降帧至 30fps（跳帧渲染）并减半粒子数；提供设置项"移动端省电模式"（默认按设备自动，可手动覆盖）。
2. **backdrop-filter 预算**：移动端同屏毛玻璃层数 ≤ 3（当前底部栏/子菜单/切换按钮均使用）；超出时子菜单降级为纯色半透明。
3. **监听器卫生**：新增手势监听一律 `{ passive: true }`（仅 `touchmove` 需要 preventDefault 的切页/词云用 passive:false 并在判定后尽早 `pointercancel`）。
4. **动画降级**：`prefers-reduced-motion` 已覆盖 PV 特效；触控端追加"低电量"（`navigator.getBattery` 可用时 battery.level < 0.2）自动进入 reduced-motion 等效档。
5. **逐字歌词**：P1 已消除逐帧 layout；移动端额外关闭 14px 柔和前沿的 mask（改为硬边 clip-path），省一次 mask 重绘（可通过外观设置恢复）。

---

## 六、视觉与可用性细节

- **安全区**：已用 `env(safe-area-inset-bottom)`；补齐 `safe-area-inset-top`（刘海屏顶部按钮下移）与横屏 `safe-area-inset-left/right`。
- **命中区清单审计**：逐项核查现有控件——顶部 6 圆钮（40px，需 +4px）、歌词偏移按钮（32px，需扩）、更多/倍速子菜单项（行高 36px，需扩至 44px）。
- **hover 态清理**：`@media (hover: hover)` 包裹所有 `:hover` 样式，避免触屏"粘性 hover"。
- **字号弹性**：歌名/歌词在窄屏用 `clamp()` 随视口缩放，避免长外文歌名溢出。
- **触觉反馈**（P2，渐进增强）：`navigator.vibrate?.(10)` 用于切歌、切页、长按菜单弹出。

---

## 七、横屏策略

- 高度 ≥ 400px 的横屏：维持双页布局但改为**左右分栏**（左播放控件右歌词，切换按钮隐藏），等效平板体验。
- 高度 < 400px（手机横屏）：显示"横屏体验更佳"轻提示（可关闭），布局仍用双页纵向滚动兜底。

## 八、实施分期与验收

| 期 | 内容 | 验收标准 |
|---|---|---|
| P0 | 滑条 Pointer 化 + 热区扩展、双页横滑切页、滚动保护窗、touch-action 体系、hover 隔离、safe-area 补齐 | 全部高频操作单手完成；无手势互相误触；iOS Safari/Android Chrome 实机流畅 |
| P1 | 长按行菜单、边缘切歌手势、可视化降帧档、命中区审计整改、毛玻璃预算 | 触控延迟 < 100ms；中端安卓（4 核）帧率 ≥ 30fps |
| P2 | 歌词拖动条、pinch 缩放词云、双击封面暂停、触觉反馈、省电自动档 | 增强功能可独立开关，关闭后回到 P1 状态 |

**测试矩阵**：iOS Safari 16+ / Android Chrome 110+ / 微信内置浏览器 × 竖屏/横屏 × 窄宽边界（699/700/701px）× 键盘导航回归（Tab 全控件可达不受触控改造影响）。

---

## 九、风险与回退

- Pointer Events 在老 WebView（Android 6 以下）缺失 → 特性检测回退 mouse+touch 双轨（现有代码即为该形态，保留为回退路径）。
- 手势层与既有 click 体系冲突 → 所有手势仅在 `IS_TOUCH` 为真时注册，桌面零影响；出问题按模块独立回退（每个手势一个开关常量）。
