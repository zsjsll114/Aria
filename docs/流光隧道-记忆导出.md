## 三、项目级硬约束（project_memory 精选，流光隧道相关）

### ★ 流光隧道镜头防抖与分镜感（最新，已踩坑）
- **焦点目标必须纯计算**：词块 `__wordLayout` 槽位 x/y 百分比 × 视口尺寸 → 世界坐标
- **禁止 getBoundingClientRect 读词块中心**——rect 受 stageLayer 摄像机 transform 影响，会形成"镜头动→坐标变→目标变→镜头再动"的**反馈振荡**（抖动根因，已踩坑）
- 焦点只在词块切换时更新（`_focusBlockEl` 对比），逐字不抖
- 运镜旋转幅度 ≤7°（spiral/dive 只用慢速正弦），节拍脉冲 scale 微调 ≤0.015
- 聚光灯按 500ms 时间节流而非 Math.random 概率
- **分镜节奏**：`PVLyricLayout.process` 加第三参 `maxSceneLines`（默认 5，流光隧道传 2 → 每 2 句一景，12 句→6 分镜）
- shot 切换 `_applyShotShift` 给背景幕色相微偏（-18°~18°，`--hue-jitter`）增强换镜感知

### ★ 词级独立排版（仿 BV1yk4y1g7sa 妄想感傷代償連盟文字 PV）
- 句子经 `_refineBlocks` 细拆（`wordSegmenter.segmentFine` 日文 ≤4 字聚合 + 孤立单字块并入前块）后，每词块绝对定位画面槽位
- `assignWordLayouts`：10 槽位池（v/h 各半），组间 seed 偏移轮换
- 竖排（`writing-mode: vertical-rl` + `text-orientation: upright`）/ 横排 / 斜排（rotate 独立属性）交织，**绝不"一句一整行"**

### ★ waiting 态完全隐藏
- `opacity:0 + visibility:hidden + color:transparent`，未唱文本零预览，唱响由入场动画 `fill:backwards` 现形（PV 模式同款节奏感）

### ★ 深浅背景转变 + 文本反色
- `--tunnel-veil` 由段落能量驱动（0.12 深底 → 0.75 副歌亮幕，bg::after 渐变 1.2s 过渡）
- 文本墨色 `--tunnel-ink`/`--tunnel-ink-dim` 随幕反色（veil>0.45 → 深墨字）

### ★ 背景降噪
- 37 种装饰库中每句组只选 2-3 种（第 1 种主角 opacity 0.55，陪衬 0.22），纹理层透明度减半

### 其他硬约束（通用）
- 所有歌词高亮过渡必须左右平滑渐变填充（情感词与非情感词）
- 多语言字体需独立 font-family（MultiLangFont-en/ko 等）防回退冲突
- 播放回退链：ygking(master→atmos→flac→320→128)→moeyao→vkeys→酷狗同名→咪咕同名→网易云同名，所有 fetch 8s AbortController 超时
- 免费音乐 API（vkeys/byfuns/ygking）需 byfuns 跨质量等级重试（exhigh/lossless/higher/standard/hires）再回退 163.com outer URL
- FontFace unicode-range 必须合法区间（start ≤ end）
- 音量赋值钳制 0~1 防 IndexSizeError
- 歌词点击跳转 currentTime 钳制 ≥0
- 停滞自愈：8s 无进度/stalled/9s 无数据→回退 2s 续播；同一位置连续 3 次无效→整曲重试；需 recovery 锁 + stallSeq 代际
- 无缝续流 `_try_seamless_tmp_stream`：本地 .tmp 残片与上游续流拼成同一 206 响应
- 缓存重建同时删 .tmp 和 .meta；记录上游真实 Content-Type
- 内嵌页面资源加载会导致 API 路由错误（返回 HTML）→ 必须 HTTP 加载
- 标题栏 z-index:100000；主容器预留 `--titlebar-height`
- 桌面歌词：动态获取 `window.__TAURI__`（每次调用，非模块加载时捕获）+ 100ms 重试最大 4s
- 8001 端口 single instance

## 五、⚠️ 当前未解决 BUG（新对话第一步）

**现象**：用户反馈"全部没有歌词了"——流光隧道模式下歌词完全不显示。

**排查线索（基于代码推理）**：
1. **最可疑**：waiting 态 CSS 改为 `opacity:0 + visibility:hidden` 后，若入场动画（WAAPI `fill:'backwards'`）没被触发或元素不在视口内，字符会永远保持隐藏。需检查：
   - `.tunnel-char.waiting` 的 `visibility:hidden` 与 WAAPI `fill:'backwards'` 动画的时序竞争（动画生效需在帧提交前，visibility 由 class 控制的等待态可能在动画开始前先应用）
   - `_buildShotBlocks` 里 `playEnterAnimation` 是否在元素挂载后立即调用（元素需在 DOM 中才有动画）
2. **词级绝对定位**：`.tunnel-block { position:absolute }` + `.tunnel-shot { position:absolute; inset:0 }`，若 `.tunnel-group-words` 容器高度/宽度为 0（`.tunnel-group` 是 absolute inset:0 但 wordsHost 是 absolute inset:0 flex），槽位百分比定位可能溢出或被裁剪。检查 `.tunnel-shot` 是否真的铺满视口。
3. **场景渲染条件**：`_renderScene` 依赖 `director.build` 的 sections；`update()` 里 `findShotAt(timeMs)` 若返回的 shot 无 line/block（分词失败）则无字符。
4. **z-index/层级**：`.tunnel-layer-stage` z-index:20，装饰层 z-index:2，粒子 z-index:26，白闪 z-index:40——检查是否被粒子/白闪/底部控制栏遮挡。
5. **动画 fill:backwards + visibility**：WAAPI `fill:'backwards'` 会应用首帧关键帧，但 `visibility:hidden` 是 CSS 类，若元素初始 hidden，浏览器可能不参与布局/动画。**建议**：把 waiting 隐藏改为仅 `opacity:0`（保留布局），或入场动画同时驱动 visibility。

**建议调试方式**：启动本地服务器 → 打开 http://localhost:8001/index.html → 切到流光隧道 → DevTools 检查 `.tunnel-view-container` 下是否有 `.tunnel-group`/`.tunnel-char` 节点、它们的 visibility/opacity/动画状态。
