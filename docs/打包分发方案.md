# 打包分发方案（免用户安装 Python / Node 环境）

> 目标：让没有 Python、Node.js 环境的普通用户也能直接运行 Aria。
> 适用范围：所有依赖本地后端的运行方式（Tauri 桌面版 / Chromium 版 / 网页版）。

---

## 0. 当前实施状态（2026-09-07 更新）

### ✅ 已落地：便携免安装版（方案 B，含 Tauri 桌面端）
- 交付物：`dist/AriaPortable/`（目录）与 `dist/Aria-Portable.zip`（约 187MB 压缩）。
  - **目录名/ZIP 名/包内启动脚本名必须纯 ASCII**：中文名在部分解压工具（老 WinRAR/国产解压）乱码，是"发给别人 8001 404"的高危因素。包内入口为 `StartAria.bat` / `StopAria.bat` / `README.txt`（中文内容、ASCII 文件名）。
- 结构：`AriaPortable/{Aria.exe, server.exe, runtime/node.exe, web/, scripts/shazam-server.mjs, node_modules/{shazamio-core,@ffmpeg-installer}, _eval/{三个vendor}, cache/(空), local_music/(空), src-tauri/icons/, StartAria.bat, StopAria.bat, README.txt}`。
- 双入口：双击 `Aria.exe` 桌面窗口版（Tauri，透明标题栏/桌面歌词，无黑框）；双击 `StartAria.bat` 网页版（server 无窗口后台运行，浏览器打开 8001）。
- **一键打包脚本 `build_portable.bat`**（纯 ASCII，`build_portable.bat [skip-tauri]`）：PyInstaller(--noconsole) → cargo release → 组装 dist/AriaPortable（robocopy 显式复制 + 排除用户数据）→ integrity spot-check → `tar -a -c -f` 压缩 → zip 成员与个人数据校验。重打产物只需双击该脚本。
- **用户数据绝不入包**：新流程改为"显式复制白名单"（不再整目录拷贝），`user_config.json / recognize_cache.json / cache/* / local_music/* / server_*.log / *.pyc` 等测试期/个人数据不会进入绿色版；`cache/` 与 `local_music/` 以空目录随包，首次运行为全新环境。
- **shazam 识曲已随包**：`scripts/shazam-server.mjs` + 精简 `node_modules`（仅 shazamio-core 3MB + @ffmpeg-installer ffmpeg.exe 61MB）随包；`server.py` 启动时后台自动拉起 18089（`_ensure_shazam_sidecar`，复用 `ARIA_NODE→runtime/node.exe→PATH` 三级解析，CREATE_NO_WINDOW 无窗口），Tauri 版由 lib.rs 拉起 —— 网页版/桌面版识曲均可用（/health 验证 `{shazamioCore:true, ffmpeg:true}`）。
- **全部进程无黑框**：`server.exe` 用 `--noconsole`（GUI 子系统，PE Subsystem=2）打包，stdout/stderr 自动回落到 `server_console.log`；`lib.rs` 的 sidecar spawn 全部加 `CREATE_NO_WINDOW`（0x08000000）；`selfhost_service` 的 vendor Popen 原已有 CREATE_NO_WINDOW；`_kill_port_occupant` 的 netstat/taskkill 子进程也加 CREATE_NO_WINDOW。
- 完整验证过：脱离 python/node 环境，8001(index.html 200) + 18089(shazam /health 200) + 3100/3200/3201 三 vendor 副进程全部就绪；登录态从 `cache/selfhost_login.json` 恢复（未受污染，新包无登录态）。

### 复现/重打包步骤（供后续维护）
> 首选：直接双击根目录 `build_portable.bat`（一键全流程，含校验）；以下为手工等价步骤。
1. `pyinstaller --noconfirm --clean --onefile --noconsole --name server --paths . server.py` → `dist/server.exe`（**必须 --noconsole**，否则启动弹黑框）
2. `cargo build --release`（src-tauri）→ `src-tauri/target/release/aria-player.exe` → 复制为 `AriaPortable/Aria.exe`（lib.rs 已适配：EXE 同级优先 server.exe/runtime/node.exe，dev 回退 PATH；sidecar spawn 已带 CREATE_NO_WINDOW）
3. 便携 node：复制 `node.exe` → `AriaPortable/runtime/node.exe`
4. 复制 `web/`、`scripts/shazam-server.mjs`、精简 `node_modules`（shazamio-core + @ffmpeg-installer）、`_eval/{qq-music-api-node,KuGouMusicApi,NeteaseCloudMusicApi}`（去 `.git`）、`src-tauri/icons/` —— **切勿**复制 `user_config.json`/`cache/`/`local_music/` 等用户数据
5. `tar -a -c -f Aria-Portable.zip -C dist AriaPortable`

### 打包踩坑清单（重要）
- **frozen 路径**：`server.py`/`local_music_server.py`/`selfhost_service.py` 的基目录必须 `os.path.dirname(sys.executable)`（onefile 下 `__file__` 指向临时解压目录）；已统一 `_PROJECT_DIR`/`BASE_DIR`。
- **`_find_node()` 三级解析**：`ARIA_NODE` 环境变量 → `PROJECT_DIR/runtime/node.exe` → PATH；启动 bat 内 `set "ARIA_NODE=%~dp0runtime\node.exe"`。
- **QQ vendor 去 npx**：绿色版无 npx → `_SERVICES['qq']['start']` 改为 `node node_modules/tsx/dist/cli.mjs src/app.ts`（tsx 已本地化在 vendor 的 node_modules）。
- **复制 vendor 必须校验完整性**：`Copy-Item -Recurse` 后检查 `node_modules/tsx/dist/cli.mjs`、`node_modules/express`、`src/app.ts` 存在；坑过：目标出现多余嵌套同名目录+`.git` 进包（255MB）→ 复制后应删除 vendor 内 `.git` 并核对大小与源一致。
- **server.py 静态根多候选回退**：`web/` 可能位于 exe 同级/`dist/app/web`/上级，找不到 index.html 时启动日志明确警示（避免"服务在跑却 404"）。
- **bat 启动脚本必须纯 ASCII**（不能有中文/chcp 65001，GBK 代码页会解析错闪退）；并做完整性预检（server.exe/web\index.html/runtime\node.exe 缺失给英文提示）。
- **对方 8001 404 排查**（已写入使用说明.txt）：多为 zip 传输损坏/部分解压/手动拆分文件 → 重下、核对大小、7-Zip 全量解压、三要素同一目录。

## 1. 现状盘点

| 组件 | 实现 | 端口 | 启动方式 | 打包时处理 |
|---|---|---|---|---|
| 主后端 | `server.py`（Python，纯标准库） | 8001 | `python server.py` | PyInstaller → `server.exe` |
| 识曲服务 | `scripts/shazam-server.mjs`（Node） | 18089 | `node`（可选功能） | 便携 node 运行 或 随包跳过 |
| QQ vendor | `_eval/qq-music-api-node`（Node/tsx） | 3200 | `npx tsx src/app.ts` | **需改启动命令**（见 3.4） |
| 酷狗 vendor | `_eval/KuGouMusicApi`（Node） | 3100 | `node app.js` | 便携 node 直接跑 |
| 网易云 vendor | `_eval/NeteaseCloudMusicApi`（Node） | 3201 | `node app.js` | 便携 node 直接跑 |
| 静态前端 | `web/`（已被 server.py 托管） | — | — | 随包放置，零处理 |
| 桌面壳 | `src-tauri`（Rust） | — | — | `externalBin` + resources |

**关键结论**：
- Python 侧**零第三方依赖**（`http.server`/`urllib` 全部标准库），PyInstaller 单文件打包非常干净。
- Node 侧**不需要把 vendor 编译成 exe**：只要带一个便携版 `node.exe`（Node 官方 Windows zip，约 70MB）和 vendor 目录即可；Rust 由「PATH 里找 python/node」改为「在安装目录里找运行时」。
- `server.py` 静态根固定为 `web/` 目录（`DIRECTORY = WEB_DIR`），前后端共享同一份文件，天然适合整目录分发。

## 2. 方案总览与推荐

| 方案 | 交付物 | 用户操作 | 工作量 | 推荐度 |
|---|---|---|---|---|
| **A. 单安装包** | NSIS/MSI 安装程序（内嵌 server.exe + node + vendor + web） | 双击安装 → 打开桌面图标 | 中 | ★★★ 正式分发首选 |
| **B. 便携免安装版** | 一个目录 + `StartAria.bat` | 解压 → 双击 bat | 低 | ★★ 网盘/优盘分发 |
| **C. 云端版** | 部署到 VPS，前端 API_BASE 指远程 | 打开网页 | 低 | ★ 需服务器、易风控 |
| **D. 去 Node 版** | 单文件 exe（纯 Python） | 双击运行 | 高 | ★ 长期演进目标 |

A 与 B 的底层打包材料（server.exe、便携 node、vendor 瘦身）完全一致，先做好「分发目录」，再决定包成安装程序还是 zip。

## 3. 方案 A/B 公共步骤（先产出「分发目录」）

### 3.1 目录目标结构（建议 `dist/app`）

```
dist/app/
├── Aria.exe                 # Tauri 壳（或 web 版跳过）
├── server.exe              # PyInstaller 单文件（8001）
├── runtime/node.exe        # 便携 Node（18089、三个 vendor 共用）
├── runtime/shazam-server.mjs
├── vendors/
│   ├── qq-music-api-node/   # 启动入口改为 dist/ 产物（见 3.4）
│   ├── KuGouMusicApi/
│   └── NeteaseCloudMusicApi/
├── web/                    # 静态前端（含 cache/config）
├── cache/                  # 运行期可写（登录态/缓存/封面）
├── local_music/            # 本地音乐
└── StartAria.bat / StopAria.bat
```

### 3.2 Python 侧打包（简单）

```bat
pip install pyinstaller
cd 项目根
pyinstaller --noconfirm --onefile --console ^
  --name server ^
  --paths . ^
  server.py
:: 产物：dist/server.exe
```

- 依赖仅为 `server.py` + `local_music_server.py` + `qq_resolver.py` + `agg_resolver.py` + `selfhost_service.py`（同目录，`--paths .` 即可收集）。
- 验证：脱离 Python 环境双击 `server.exe`，浏览器打开 `http://127.0.0.1:8001/index.html` 正常。
- ⚠ 风险：Windows Defender 偶尔误报 PyInstaller 单文件；可升级 PyInstaller 版本、对 exe 数字签名（收费）或换用 `--onedir`（误报率更低）。

### 3.3 Node 运行时（便携）

1. 下载 Node 官方 **Windows x64 zip**（如 `node-v20.x-win-x64.zip`，约 30MB 压缩 / 70MB 解压），只取 `node.exe` 放入 `runtime/`。
2. 启动任何 node 进程一律用 `runtime\node.exe` 绝对路径（不再用 PATH）。

### 3.4 QQ vendor 的启动命令改造 ★ 关键坑

当前启动是 `npx tsx src/app.ts`，依赖全局 npx/tsx。两种改法，**推荐 ①**：

**① 本地化 tsx（改动最小）**
- 在 `_eval/qq-music-api-node` 里 `npm i -D tsx`（体积较大，瘦身时可删）。
- `selfhost_service.py` 的 `_SERVICES['qq']['start']` 改为：
  `node node_modules/tsx/dist/cli.mjs src/app.ts`
  （打包后整体用 `runtime\node.exe` 前缀运行，见 3.5 的运行时解析改造。）

**② 预编译（体积最小）**
- `npx tsc -p tsconfig.json`（或 `esbuild src/app.ts --bundle --platform=node --outfile=dist/app.js`），把入口与依赖捆成单文件。
- `start` 改为 `` `node dist/app.js` ``。
- 注意：tsx 依赖 esbuild 动态加载，`pkg`/esbuild 打包**原生模块**（如部分 crypto 路径）可能失败，因此本方案始终建议「便携 node + 原目录」而非把 vendor 编译成 exe。

### 3.5 Rust 侧改造（Tauri 版分发目录时）

[lib.rs](src-tauri/src/lib.rs) 目前用 `Command::new("python")` / `Command::new("node")` 从 PATH 查找，改为：

1. 运行时根目录解析（开发环境回退到项目根，打包后指向资源目录）：
```rust
fn runtime_root() -> PathBuf {
    // 开发：CARGO_MANIFEST_DIR/..  打包：self::resource_dir() 或 exe 同级 dist/app
    if let Ok(r) = tauri::api::process::current_binary_dir() {
        r.join("dist/app")
    } else {
        PathBuf::from(env!("CARGO_MANIFEST_DIR")).join("..")
    }
}
```
2. 所有 `Command::new("python")`/`node` 换成：
   - `server` → `runtime_root().join("server.exe")`
   - node → `runtime_root().join("runtime/node.exe")`
   - `selfhost_service.ensure_running` 的 node 启动路径通过环境变量注入：启动 `server.exe` 时设置 `ARIA_NODE=runtime/node.exe`，`selfhost_service._find_node()` 优先读该变量。
3. `spawn_sidecars` 的探测仍等待 8001 就绪即可，判断方式不变。

### 3.6 Tauri 打包装配（方案 A）

- `tauri.conf.json`：
  - `bundle.externalBin`：`["binaries/server", "binaries/runtime-node"]`（Tauri 会自动加 `-x86_64-pc-windows-msvc.exe` 后缀，需对应命名）；
  - 或更简单：`bundle.resources` 把 `dist/app` 整个目录拷进安装目录，Rust 从资源目录启动（与 3.5 结合，最不易出错）。
- `bundle.targets`：`"nsis"` / `"msi"`（Community 版可用 NSIS）。
- 窗口 URL 保持 `http://localhost:8001/index.html`（远程协议，静态资源由 server.exe 提供），`frontendDist` 仅作占位。

### 3.7 瘦身清单（分发前必做）

| 项 | 动作 | 省出 |
|---|---|---|
| 三个 vendor 的 node_modules | `npm prune --production`（保留 devDependency 中 tsx；其余删） | ~40-60% |
| QQ vendor 若走方案 3.4-② | tsc 编译后仅留 dist/ + 必要依赖 | 最大 |
| vendor 内 docs/tests/scripts | 删除 | 若干 MB |
| 根目录 node_modules（171MB） | 仅 shazam 需要 → 打散进 `runtime/`，其余删除 | ~150MB |
| `_eval/*/node_modules` 未用大件 | 逐个 `du` 核对后删除 | — |

## 4. 方案 B：便携免安装版

- 就是 3.1 的 `dist/app` 目录 + bat。新增两份启动脚本：
  - `StartAria.bat`：`start "" server.exe` + 等 3s 后 `start "" http://127.0.0.1:8001/index.html`（网页版；Aria.exe 桌面壳则由 Aria.exe 自启动 server.exe）
  - `StopAria.bat`：taskkill 清理 server.exe / node.exe（关 Aria 窗口即自动回收进程树，双保险）
- 打包：`tar -a -c -f Aria-便携版.zip dist/app` 直接交付。
- 让用户放非中文/无空格路径（Windows 批处理与 vendor 路径带中文易出问题）。

## 5. 方案 C：云端版（备忘，非首选）

1. `web/src/config/constants.js` 的 `API_BASE` 改成 `https://你的域名`，其余接口（`/api/...`、`/proxy`）随 server.py 一起部署。
2. 部署 server.py 到 VPS（systemd 常驻），代理 8001 到 80/443。
3. 用户零本地依赖（浏览器直开），但：签名/风控接口依赖出口 IP 与 UA，易被封；登录 Cookie 存在服务器内存，多用户共享有隐私风险。**不建议作为默认分发方式。**

## 6. 方案 D：去掉 Node（长期目标）

把三个 vendor 的协议用 Python 重写（`requests`/自建签名）：
- **网易云**（较简单）：`login_qr_key/check`、`recommend/songs`、`toplist`、`playlist/track/all` 都是公开 JSON 接口，仅需补签名。
- **酷狗**：`playlist/track/all`、`user/playlist`、`youth/vip` 需 android 签名（已有 Python 侧 checkin 先例），工作量中等。
- **QQ**（最重）：登录四段流程（ptlogin → oauth 授权 → musicu.fcg 换 token）+ `zzcSign` 签名 + TLS 指纹绕行（现已证明 axios 被 c6 风控、undici 可以，Python 侧需验证 https 层等价性）。
- 完成后再把 `selfhost_service` 的 subprocess 启动改为进程内直接调用，最终 `server.exe` 单文件即可运行，体积最小。
- 建议作为 2.0 演进，先交付 A/B。

## 7. 实施顺序建议（A 为主线）

1. **今天可做**：PyInstaller 打包 + 便携 node 落位 → `dist/app` 雏形（B 版即可分发）。
2. **本周**：QQ vendor 启动改造（3.4 ①）→ 三个 vendor 瘦身（3.7）→ 全链路脱离 PATH 验证。
3. **随后**：Rust 侧资源路径改造（3.5）→ `externalBin`/`resources` 装配 → NSIS 安装程序。
4. **机动**：方案 D 的网易云 Python 化（收益最大、成本最低的一块）。
