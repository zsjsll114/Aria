## 一、上游参考项目的做法（调研结论）

1. **全屏弹窗**（非侧滑抽屉），顶部两个主 tab：`帮助 / 设置`；弹窗四角彩色光斑毛玻璃装饰。
2. **声明式导航模型是唯一事实源**（settingsNavModel.ts）：
   - 9 个 section（appearance / general / playback / interaction / integration / storage / desktop / lab / developer）
   - 归并为 4 组（外观组、控制组、连接组、系统组）
   - 每项带 `icon + label + description + anchors`（节内二级锚点）
   - 平台过滤（web 自动剔除 electronOnly 的 desktop 组）
3. **双层导航**：宽屏左侧栏 / 窄屏横向胶囊条（同一份数据两种渲染）；scroll-spy 滚动监听高亮当前节；节内锚点直达。
4. **卡片化内容**：每个 section 由若干 Section 卡片组成；卡片样式抽成独立常量（`bg-white/5 border-white/5`），命令面板可复用渲染。
5. **状态分域 store**：每个领域一个 store（视觉/歌词/播放…），Modal 只做快照选择与分发。
6. **About 在帮助 tab 底部**：作者行、版本 chip（点击复制）、下载入口卡片组、快捷键列表。

## 二、Aria 现状盘点（2026-10-07 复核，已与实现对齐）

- 入口：右上角齿轮 → `#settingsPanel`；**已有声明式导航 + 分组侧栏**：
  `web/src/config/settingsNav.js` 是唯一事实源（4 组 × 13 项、双语 `labelEn`），
  由它渲染侧栏，切换收敛到 `window.switchSettingsTab`（含各节副作用）。
  分区（`data-section`，13 个）：appearance / background / fonts / playback / quality /
  audio / performance / selfhost / ai / data / interface / shortcuts / about。
- 外观域**已是"先选模式再出设置"**：`.appearance-mode-btn[data-mode]` 分段控件 +
  `[data-mode-section]` 单显（`202-settings-appearance.js` 的 `showModeSection`）。
- 仍存在的问题：
  1. **单个模式区块会很长**：新加的「字面 · Jizura」一个区块约 20 行（风格/情绪/性能档/
     动画节拍/按字切分镜/画面细节 8 项/日文字体包/帧率/翻译/字体）。原文"消除最长的那段
     滚动"这个目标因此**被重新推高**——需要节内锚点（§三·阶段 2 的 anchors）。
  2. **控件行样式靠约定，没有强制**：`.settings-group`（卡片）与 `.setting-row`（label +
     控件）已在用，但"三栏网格 + 统一行高"没有约束，模块各写各的。
  3. **搜索缺失**：`SETTINGS_NAV` 没有 `keywords`/`anchors`，设置项无索引。

### 二·补 2026-10-07 两条实测教训（都是"面板看起来有、实际没接线"）

1. **`data-var` 型下拉根本没绑**（真实漏洞，用户报障"设计分辨率/帧率没用"）：
   面板里的下拉有三套来源 —— `data-setting` 型由 `220` 绑、字体下拉由 `215` 绑，
   **手写 `data-var` 型此前谁也没绑**（`202` 的绑定器只认 `.setting-slider` /
   `.setting-btn-group .setting-btn` / `.setting-toggle`）。症状：菜单能展开（开合由 220 挂）、
   点选项毫无反应、设置写不进去。已在 `202` 补齐绑定与回显（含"开合只挂一次"的
   `_ariaToggleBound` 约定，避免与 220 的双 handler 互相抵消）。
   ⇒ **教训：「控件存在」≠「控件接线」。** 守卫见 `scratch/_jizura_panel_check.py`：
   逐个点击每个控件、断言值真的落进设置（当前 16 个控件、0 死）。
2. **`res` 是个安慰剂键**：引擎从不读 `project.res`——
   `08_planner.js:283 const [W,H] = J.designSize(project.aspect)`，而
   `J.designSize = (aspect) => …` 按 aspect 返回硬编码尺寸（16:9 → 1920×1080）。
   ⇒ 面板项已撤、字段已从 defaults/schema/配方移除，适配层留注释说明。
   **教训：给引擎加参数前，先确认引擎真的读它**（否则就是一个"改了没反应"的控件）。
3. **设置页不是单一滚动容器**（2026-10-07，节内锚点踩到）：外观页是 flex 分栏，
   内容由块内的 `.appearance-controls`（`#lyricStyleControls`）自己滚，其余节才是
   `#settingsBody` 滚（后者设 `scrollTop = 0` 在外观页其实是空操作）。
   ⇒ 定位一律用 `scrollIntoView`（既有深搜跳转就是这么做的），**不要自己算 scrollTop**
   —— 算就得先猜对容器，猜错的表现正是"点了没反应"。
4. **面板 DOM 会滞后于设置**（2026-10-07，守卫脚本自身踩到）：滑杆可能显示 0.70 而
   `modeSettings.jizura.motion` 已是 0.75、按钮组的 `.active` 也可能与已存值不一致。
   ⇒ 守卫脚本的"点一下看设置变没变"必须**由持久化设置推导目标值**，照 DOM 递增会
   "写回同一个值"从而误报成死控件（当时误报 10 个；用 setter 陷阱抓到
   `from 0.75 → to 0.75` 才定位）。

## 三、重构方案（三阶段）

### 阶段 1：信息架构重组 ✅ 已完成（2026-10-07 复核）
- 声明式导航模型：`web/src/config/settingsNav.js`（4 组 × 13 项、双语）。
- 侧栏由该表生成，点击走 `window.switchSettingsTab`（唯一收敛的切换函数）。
- 外观域的"9→10 个模式分栏"已是二级列表形态（模式分段控件 + 单显区块）。
- **仍缺**：nav 项的 `icon`、`description`、`anchors`、`keywords`（阶段 2/3 要用）。

### 阶段 2：卡片化 + 视觉统一 ✅ 已完成（2026-10-07）
- 卡片化：`.settings-group` 已是"组 = 一张卡片"（`modals.css:265`，行内去独立底色、
  行间细分隔线）。
- 控件归一：`data-var` 控件已由**一套绑定器**覆盖全部类型
  （滑杆 / 开关 / 按钮组 / **下拉**，见 §二·补 1），并配"死控件"守卫。
- **节内锚点已落地**（`settingsNav.js:refreshSectionAnchors`，2026-10-07）：
  挂在激活节下方、缩进 + 左侧细线；点击 `scrollIntoView` 到该组并闪烁；
  滚动跟随（触底特例 + 点击后 900ms 锁定，避免"最后一组永远高亮不到"）；
  搜索时自动让位。**锚点由 DOM 派生**（组标题 → 锚点），加一个组就自动多一个锚点。
  窄屏（≤640px）侧栏是横滑胶囊条，锚点隐藏（手机上定位靠搜索）。
- 仍可选（未做，优先级低）：控件行统一三栏网格（label / 控件 / 当前值）；
  滑杆与下拉宽度对齐。当前 `justify-content: space-between` 的观感已一致，
  属纯美化，改动面大、收益小。

### 阶段 3：搜索 ✅ 已实现（复核修正：2026-10-07 之前就已落地）
- `settingsNav.js` 顶部搜索框：按节名/组名过滤 **+ 跨节深搜**
  （扫 `.setting-label/.setting-desc/.settings-group-title`）、命中计数徽章、
  点击节后滚到首个命中行并闪烁（`200-settings-panel.js:76-80` 的 `scrollIntoView`）。
- ★ 之前的文档版本把这一节写成"未做"，是**错的**（照它施工会重复造一遍）。
  实践也证明"nav model 加 keywords"这条原计划被更好的方案取代了：**直接从 DOM 深搜**，
  设置项一多也不会漏同步（和锚点同一条思路）。
- 仍未做（可选）：Ctrl+K 命令面板复用同一 nav model 渲染。

## 四、迁移注意

1. 现有绑定按 `data-section` 与 id 挂接（200/201/202/215 各管一域）——重构**只动容器与
   导航壳，不动绑定逻辑**：各域 init 函数保持，仅 DOM 宿主重新归位；
2. `initAboutLinks` / `openExternalUrl` 已独立成函数，随 about 节迁移；
3. 移动端（--lan 手机访问）必须验证胶囊条布局；
4. **新增绑定风格（2026-10-07）**：`309-jizura-fontpack.js` 用 MutationObserver 补绑按钮
   （设置面板会被反复重建）。它与"各域 init 保持"不冲突，反而更抗 DOM 迁移；
   但**新写的控件若走这条路，必须把它写进本文件**，否则日后按旧写法会漏绑。
5. 分阶段提交：阶段 1 一个 commit，阶段 2/3 各自独立，便于回退。
