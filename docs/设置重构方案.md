# 设置面板重构方案（上游参考项目 对齐）

> 现状问题：设置项平铺堆叠、无分组导航、找一项要滚动很久；视觉上控件密度不均。
> 参考：上游参考项目 `src/components/modal/SettingsModal.tsx` + `modal/settings/` 子目录
> （navigation/settingsNavModel.ts 声明式导航模型、滚动监听、卡片化、zustand 分域 store）。

## 一、上游参考项目的做法（调研结论）

1. **全屏弹窗**（非侧滑抽屉），顶部两个主 tab：`帮助 / 设置`；弹窗四角彩色光斑毛玻璃装饰。
2. **声明式导航模型是唯一事实源**（settingsNavModel.ts）：
   - 9 个 section（appearance / general / playback / interaction / integration / storage / desktop / lab / developer）
   - 归并为 4 组（外观组、控制组、连接组、系统组）
   - 每项带 `icon + label + description + anchors`（节内二级锚点）
   - 平台过滤（web 自动剔除 electronOnly 的 desktop 组）
3. **双层导航**：宽屏左侧栏 / 窄屏横向胶囊条（同一份数据两种渲染）；scroll-spy 滚动监听高亮当前节；节内锚点直达。
4. **卡片化内容**：每个 section 由若干 Section 卡片组成；卡片样式抽成独立常量（`bg-white/5 border-white/5`），命令面板可复用渲染。
5. **状态分域 store**：每个领域一个 store（视觉/歌词/播放…），Modal 只做快照选择与分发。
6. **About 在帮助 tab 底部**：作者行、版本 chip（点击复制）、下载入口卡片组、快捷键列表。

## 二、Aria 设置面板现状盘点

- 入口：右上角齿轮 → `#settingsPanel` 右侧滑出（`200-settings-panel.js` + `202/201/215` 等分片）。
- 分区（`data-section`）：interface / lyrics / appearance(外观) / selfhost / ai / about 等平铺；
  外观域内再按视觉模式分 9+ 个子分栏（每模式独立字号/颜色/字体/开关）。
- 问题：
  1. **层级扁平**：所有 section 平级列表，外观域内 9 个模式分栏撑长页面；
  2. **无导航**：找不到「均衡器在哪」「字体在哪」，只能滚动扫；
  3. **控件密度不一**：有的节全是滑杆、有的节全是开关，无卡片边界；
  4. **搜索缺失**：设置项无索引。

## 三、重构方案（三阶段）

### 阶段 1：信息架构重组（不改视觉框架，收益最大）
- 引入**声明式导航模型** `settingsNavModel.js`（唯一事实源）：
  ```js
  export const SETTINGS_NAV = [
    { group: '外观', items: [
      { id: 'appearance', label: '视觉模式', icon: 'palette', desc: '九种模式的字号颜色字体' },
      { id: 'lyrics', label: '歌词', icon: 'text', desc: '对齐/模糊/高亮/翻译' },
      { id: 'fonts', label: '字体', icon: 'font' },
    ]},
    { group: '播放', items: [
      { id: 'playback', label: '播放', icon: 'play' },
      { id: 'eq', label: '均衡器', icon: 'eq' },
      { id: 'shortcuts', label: '快捷键', icon: 'keyboard' },
    ]},
    { group: '服务', items: [
      { id: 'selfhost', label: '自建服务', icon: 'cloud' },
      { id: 'ai', label: 'AI 分析', icon: 'sparkle' },
      { id: 'recognize', label: '听歌识曲', icon: 'mic' },
    ]},
    { group: '系统', items: [
      { id: 'storage', label: '存储与缓存', icon: 'database' },
      { id: 'about', label: '关于', icon: 'info' },
    ]},
  ];
  ```
- 左侧栏（宽屏）/顶部胶囊条（窄屏）双渲染，scroll-spy 高亮；
- **外观域的 9 个模式分栏改为二级列表**：先选模式（图标网格）再出该模式的设置——
  消除最长的那段滚动。

### 阶段 2：卡片化 + 视觉统一
- 每个逻辑组包进卡片（`bg 5% / 边框 6% / 圆角 12px`，标题+描述+控件三段式）；
- 控件行统一三栏网格（label / 控件 / 当前值），滑杆/开关/下拉同一行高；
- 沿用现有 `--theme-color` 变量体系，不引入新主题机制。

### 阶段 3：搜索与命令面板（进阶）
- nav model 每项加 `keywords`，顶部搜索框过滤（输入「字体」直接跳到字体节并高亮）；
- 可选：Ctrl+K 命令面板复用同一 nav model 渲染（上游参考项目的做法）。

## 四、迁移注意

1. 现有绑定按 `data-section` 与 id 挂接（200/201/202/215 各管一域）——重构**只动容器与
   导航壳，不动绑定逻辑**：各域 init 函数保持，仅 DOM 宿主重新归位；
2. `initAboutLinks` / `openExternalUrl` 已独立成函数，随 about 节迁移；
3. 移动端（--lan 手机访问）必须验证胶囊条布局；
4. 分阶段提交：阶段 1 一个 commit（含 nav model + 侧栏壳 + 模式二级列表），
   阶段 2/3 各自独立，便于回退。

## 五、工作量估计

- 阶段 1：~4h（nav model + 侧栏壳 + scroll-spy + 外观二级列表迁移）
- 阶段 2：~3h（卡片化 CSS + 控件行网格）
- 阶段 3：~2h（搜索过滤 + 命令面板可选）
